# sceniK Backend

Spring Boot/MySQL public API server for sceniK. The frontend calls this backend
only. This service may call `sceniK-ai` internally in a later phase, but the
current MVP keeps deterministic DB-backed AI route generation available.

## Tech Stack

- Java 17
- Spring Boot 3.3.6
- Gradle Wrapper
- MySQL
- MyBatis
- Spring MVC REST API
- Bean Validation
- springdoc-openapi / Swagger UI

## Environment

Use environment variables or local Spring configuration:

```powershell
$env:DB_USERNAME = "ssafy"
$env:DB_PASSWORD = "ssafy"
```

See `src/main/resources/application-example.yml` for non-secret configuration
examples. Do not commit real credentials.

The backend optionally loads key-value pairs from the project-root `.env` file.
Process environment variables still take precedence.

## Google and Kakao OAuth

Required local variables:

```text
GOOGLE_OAUTH_CLIENT_ID=...
GOOGLE_OAUTH_CLIENT_SECRET=...
KAKAO_OAUTH_CLIENT_ID=...
KAKAO_OAUTH_CLIENT_SECRET=...
OAUTH_BASE_URL=http://localhost:8080
OAUTH_FRONTEND_REDIRECT_URI=http://127.0.0.1:5173/oauth/callback
```

Register this exact authorized redirect URI in Google Cloud Console:

```text
http://localhost:8080/login/oauth2/code/google
```

Register this exact redirect URI in Kakao Developers:

```text
http://localhost:8080/login/oauth2/code/kakao
```

Enable the Kakao Login consent items for nickname, profile image, and account email.

OAuth flow:

1. Navigate the browser to `/api/auth/oauth/google` or `/api/auth/oauth/kakao`.
2. The OAuth provider redirects back to the Spring Security callback.
3. The backend redirects to the frontend callback with a five-minute one-time `code`.
4. Exchange that code with `POST /api/auth/oauth/exchange` to receive the normal sceniK access and refresh tokens.

The one-time code is stored only as a SHA-256 hash and is consumed atomically.
Logging out through `POST /api/auth/logout` revokes the sceniK session; it does
not sign the user out of their Google or Kakao account.

## Database Reset

`src/main/resources/schema.sql` uses `CREATE TABLE IF NOT EXISTS`; it does not
migrate old local tables. Reset the local DB after schema changes.

PowerShell:

```powershell
.\scripts\reset-local-db.ps1 -User ssafy -Password ssafy
```

Bash:

```bash
./scripts/reset-local-db.sh
```

Seed CSV files live in `data/seed/`. Runtime SQL seed files live in
`src/main/resources/schema.sql` and `src/main/resources/data.sql`.

Create the demo account through `POST /api/auth/signup` so the password hash is
generated by backend code:

```json
{
  "email": "demo@scenik.com",
  "password": "password123",
  "nickname": "데모유저"
}
```
