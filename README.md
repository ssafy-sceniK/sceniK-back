# sceniK Backend

Spring Boot/MySQL public API server for sceniK. The frontend calls this backend
only. This service may call `sceniK-ai` internally in a later phase, but the
current MVP keeps deterministic DB-backed AI route generation available.

## Tech Stack

- Java 17
- Spring Boot 3.3.6
- Gradle Wrapper
- MySQL
- MyBatis
- Spring MVC REST API
- Bean Validation
- springdoc-openapi / Swagger UI

## Environment

Use environment variables or local Spring configuration:

```powershell
$env:DB_USERNAME = "ssafy"
$env:DB_PASSWORD = "ssafy"
```

See `src/main/resources/application-example.yml` for non-secret configuration
examples. Do not commit real credentials.

## Run

PowerShell:

```powershell
cd backend
.\gradlew.bat bootRun
```

Bash:

```bash
cd backend
./gradlew bootRun
```

Swagger UI:

```text
http://localhost:8080/swagger-ui/index.html
```

## Database Reset

`src/main/resources/schema.sql` uses `CREATE TABLE IF NOT EXISTS`; it does not
migrate old local tables. Reset the local DB after schema changes.

PowerShell:

```powershell
.\scripts\reset-local-db.ps1 -User ssafy -Password ssafy
```

Bash:

```bash
./scripts/reset-local-db.sh
```

Seed CSV files live in `data/seed/`. Runtime SQL seed files live in
`src/main/resources/schema.sql` and `src/main/resources/data.sql`.

Create the demo account through `POST /api/auth/signup` so the password hash is
generated by backend code:

```json
{
  "email": "demo@scenik.com",
  "password": "password123",
  "nickname": "데모유저"
}
```

## API Smoke Files

HTTP smoke files live in `api-tests/`, including Week 2 critical flow and error
case examples. Run them from an HTTP client after the backend is running.

## Notes

- `contentId` and `placeId` are string IDs from seed data.
- Keep user-facing API errors in the standardized Korean JSON format.
- Log server-side stack traces, but never expose stack traces or SQL details to
  clients.
